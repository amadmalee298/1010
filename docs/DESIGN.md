# เอกสารออกแบบระบบ POS ร้านขนมหวานคัสตาร์ด

## 1. ภาพรวม

ระบบขายหน้าร้าน (Point of Sale) ครบวงจรสำหรับร้านขนมหวานคัสตาร์ด/สังขยา รองรับตั้งแต่การรับออเดอร์ ชำระเงิน ส่งออเดอร์เข้าครัว เรียกคิวลูกค้า ตัดสต็อกวัตถุดิบตามสูตร สะสมแต้มสมาชิก ไปจนถึงปิดกะและรายงานกำไร

**เป้าหมายการออกแบบ**
- ใช้งานบนแท็บเล็ต/คอมหน้าร้าน แตะง่าย ปุ่มใหญ่ (มือถือก็ใช้ได้)
- ติดตั้งง่ายที่สุด: Node.js ตัวเดียว ไม่มี dependency ภายนอก ฐานข้อมูลเป็นไฟล์ SQLite ไฟล์เดียว
- ทำงานในวง LAN ได้แม้อินเทอร์เน็ตล่ม (QR พร้อมเพย์สร้างในเครื่อง)
- คำนวณเงินที่เซิร์ฟเวอร์เท่านั้น (ฝั่งหน้าจอแสดงผลอย่างเดียว) ป้องกันการแก้ราคาจากเบราว์เซอร์

## 2. สถาปัตยกรรม

```
┌──────────── อุปกรณ์ในร้าน (เบราว์เซอร์) ────────────┐
│  แท็บเล็ตแคชเชียร์   จอครัว (KDS)   จอเรียกคิว   มือถือเจ้าของ │
└───────────────┬──────────────────────────────────┘
                │ HTTP/JSON (LAN หรืออินเทอร์เน็ต)
┌───────────────▼──────────────────────────────────┐
│ Node.js server (server/index.js)                    │
│  ├─ http.js     router + static files + validation  │
│  ├─ api.js      REST API + สิทธิ์ตามตำแหน่ง           │
│  ├─ pricing.js  ตรรกะคำนวณราคา (pure, มี unit test)  │
│  └─ promptpay.js สร้าง payload EMVCo + CRC16         │
└───────────────┬──────────────────────────────────┘
                │ node:sqlite (WAL, transaction)
          ┌─────▼─────┐
          │ data/pos.db │
          └───────────┘
```

| ชั้น | เทคโนโลยี | เหตุผล |
|---|---|---|
| Frontend | HTML + CSS + Vanilla JS (ES Modules) แบบ SPA | ไม่ต้อง build, โหลดเร็วบนแท็บเล็ตราคาถูก |
| Backend | Node.js 22+ `node:http` | ไม่มี dependency ให้ดูแล |
| Database | SQLite (`node:sqlite` ในตัว Node) | ไฟล์เดียว สำรองง่าย (copy ไฟล์) รองรับร้านขนาดเล็ก-กลางสบาย |
| QR | qrcode-generator (MIT) เก็บไว้ใน `public/vendor` | ใช้ได้แบบออฟไลน์ |

## 3. ผู้ใช้และสิทธิ์ (RBAC)

เข้าสู่ระบบด้วยการเลือกชื่อ + PIN 4-6 หลัก (เก็บแบบ scrypt hash + salt) ได้ token อายุ 16 ชั่วโมง

| ความสามารถ | เจ้าของร้าน | ผู้จัดการ | แคชเชียร์ | ครัว |
|---|:-:|:-:|:-:|:-:|
| ขาย / ดูบิล / เปิด-ปิดกะ / สมาชิก | ✅ | ✅ | ✅ | — |
| จอครัว เปลี่ยนสถานะออเดอร์ | ✅ | ✅ | ✅ | ✅ |
| รับวัตถุดิบเข้า / บันทึกของเสีย | ✅ | ✅ | ✅ | — |
| นับสต็อก / แก้เมนู สูตร / โปรโมชั่น / รายงาน / ประวัติกะ | ✅ | ✅ | — | — |
| ยกเลิกบิล, ให้ส่วนลดเกินวงเงิน | ✅ | ✅ | ต้องใช้ PIN ผู้จัดการ | — |
| จัดการพนักงาน / ตั้งค่าร้าน / Audit log | ✅ | — | — | — |

## 4. โมดูลของระบบ

1. **ขายหน้าร้าน (POS)** — หมวดหมู่, ค้นหา (Enter = เพิ่มรายการแรก), เลือกตัวเลือก (รส/ความหวาน/ท็อปปิ้ง/ขนาด/ร้อน-เย็น) พร้อมกฎบังคับเลือก/เลือกหลายอย่าง/จำนวนสูงสุด, หมายเหตุถึงครัว, ประเภทออเดอร์ (ทานที่ร้าน/กลับบ้าน/เดลิเวอรี่), พักบิล, แสดงจำนวนที่ทำได้จากสต็อกคงเหลือ
2. **ชำระเงิน** — เงินสด (ปุ่มแบงก์ด่วน + คำนวณเงินทอน), พร้อมเพย์ QR แบบระบุยอด, บัตร, โอน/แอปเดลิเวอรี่ → พิมพ์ใบเสร็จ 80mm และใบสั่งครัว
3. **ส่วนลด** — โปรโมชั่น (% หรือบาท, ยอดขั้นต่ำ, เพดานส่วนลด, ช่วงวันที่, เฉพาะสมาชิก, โค้ด), ส่วนลดพิเศษ (วงเงินแคชเชียร์ตั้งค่าได้), แลกแต้ม
4. **สมาชิก** — ค้นด้วยเบอร์ / สมัครที่หน้าขาย, สะสมแต้ม (X บาท = 1 แต้ม), แลกแต้ม (1 แต้ม = Y บาท), ยอดซื้อสะสม, ประวัติการซื้อ
5. **จอครัว (KDS)** — 3 คอลัมน์ รอทำ → กำลังทำ → พร้อมเสิร์ฟ, รีเฟรชทุก 5 วินาที, เสียงแจ้งเตือนออเดอร์ใหม่, ไฮไลต์ออเดอร์ที่รอเกิน 10 นาที
6. **จอเรียกคิวลูกค้า** — `/#/queue` ไม่ต้องล็อกอิน แสดงเลขคิวกำลังเตรียม/พร้อมรับ (เปิดบนทีวีหน้าร้าน)
7. **สต็อกวัตถุดิบ** — สูตรต่อเมนู + วัตถุดิบเพิ่มจากท็อปปิ้ง ⇒ ตัดสต็อกอัตโนมัติเมื่อขาย, คืนสต็อกเมื่อยกเลิกบิล, รับเข้า (อัปเดตต้นทุน), ของเสีย, นับสต็อกจริง, แจ้งเตือนต่ำกว่าขั้นต่ำ, ประวัติเคลื่อนไหวทุกรายการ
8. **จัดการเมนู** — สินค้า, หมวดหมู่, กลุ่มตัวเลือก, สูตร พร้อมคำนวณต้นทุนและ GP% ต่อเมนู
9. **กะ/ลิ้นชักเงินสด** — เปิดกะด้วยเงินทอนตั้งต้น, นำเงินเข้า/ออก, ปิดกะด้วยการนับแบงก์/เหรียญ ⇒ เทียบเงินที่ควรมี แสดงส่วนต่าง พิมพ์สรุปกะ
10. **รายงาน** — ยอดสุทธิ, จำนวนบิล, เฉลี่ยต่อบิล, ส่วนลด, ต้นทุน, กำไรขั้นต้น, ยอดรายชั่วโมง/รายวัน, สินค้าขายดี, หมวดหมู่, ช่องทางชำระ, พนักงาน, วัตถุดิบใกล้หมด, ส่งออก CSV (เปิดใน Excel ภาษาไทยได้)
11. **ตั้งค่า** — ข้อมูลร้านบนใบเสร็จ, VAT (รวมใน/แยกนอก), พร้อมเพย์, กติกาแต้ม, วงเงินส่วนลดแคชเชียร์, Audit log

## 5. โครงสร้างฐานข้อมูล (ER)

```
users ─┬─< sessions
       ├─< shifts ─< cash_movements
       └─< orders >── members
              │  └──> promotions
              └─< order_items >── products >── categories
                                    ├─< product_option_groups >── option_groups ─< options
                                    └─< recipes >── ingredients ─< stock_movements
settings (key/value)   audit_log
```

| ตาราง | หน้าที่ | ฟิลด์สำคัญ |
|---|---|---|
| `products` | เมนู | price, cost (ใช้เมื่อไม่มีสูตร), icon, color, active |
| `option_groups` / `options` | ตัวเลือกเสริม | required, multiple, max_select / price_delta, ingredient_id + ingredient_qty |
| `recipes` | สูตรต่อ 1 หน่วยขาย | product_id, ingredient_id, qty |
| `ingredients` | วัตถุดิบ | stock, min_stock, cost_per_unit |
| `stock_movements` | สมุดบัญชีสต็อก | change, balance, reason (sale/void/purchase/adjust/waste), ref = เลขบิล |
| `orders` | หัวบิล | order_no (YYMMDD-NNNN), queue_no (รีเซ็ตรายวัน), สถานะครัว, สถานะชำระ (paid/void), ยอดทุกขั้น, cost |
| `order_items` | รายการในบิล | ชื่อ/ราคา/ตัวเลือก **snapshot** ณ เวลาขาย (แก้เมนูภายหลังไม่กระทบบิลเก่า) |
| `shifts` / `cash_movements` | กะและเงินในลิ้นชัก | opening_cash, expected_cash, counted_cash |
| `members` | สมาชิก | phone (unique), points, total_spent, visits |
| `promotions` | โปรโมชั่น | type, value, min_total, max_discount, members_only, start/end_date, code |
| `audit_log` | บันทึกเหตุการณ์ | login, สร้าง/ยกเลิกบิล, เปลี่ยนตั้งค่า, ปรับแต้ม ฯลฯ |

## 6. ลำดับการคำนวณยอด (server/pricing.js)

```
ราคาต่อหน่วย = ราคาสินค้า + Σ ราคาตัวเลือก       (ตรวจกฎกลุ่มตัวเลือก)
subtotal      = Σ ราคาต่อหน่วย × จำนวน
− ส่วนลดโปรโมชั่น (%/บาท, เพดาน, ขั้นต่ำ, วันที่, สมาชิก)
− ส่วนลดพิเศษ     (เกินวงเงินแคชเชียร์ ⇒ ต้อง PIN ผู้จัดการ)
− แลกแต้ม         (≥ ขั้นต่ำ, ≤ แต้มที่มี, ≤ ยอดคงเหลือ)
= ยอดก่อนภาษี
VAT: รวมใน ⇒ vat = ยอด × r/(100+r) | แยกนอก ⇒ total = ยอด + ยอด × r/100
แต้มที่ได้ = floor(total / บาทต่อแต้ม)   (เฉพาะสมาชิก)
```

## 7. Flow การขาย 1 บิล (ทั้งหมดอยู่ใน transaction เดียว)

```
แคชเชียร์เลือกเมนู → /api/orders/quote (แสดงยอดแบบเรียลไทม์)
          → กดชำระ → POST /api/orders
               1. ตรวจว่ามีกะเปิดอยู่
               2. คำนวณราคาใหม่ทั้งหมดจากฐานข้อมูล (ไม่เชื่อราคาจากหน้าจอ)
               3. ตรวจสิทธิ์ส่วนลด / เงินที่รับ
               4. ออกเลขบิล + เลขคิวประจำวัน
               5. บันทึก order + order_items (snapshot)
               6. ตัดสต็อกตามสูตร + ท็อปปิ้ง → stock_movements, คำนวณต้นทุนจริง
               7. อัปเดตแต้ม/ยอดสะสมสมาชิก
               8. audit_log
          → ออเดอร์ขึ้นจอครัว → ครัวกด "เริ่มทำ" → "ทำเสร็จ" (ขึ้นจอเรียกคิว) → "เสิร์ฟแล้ว"
ยกเลิกบิล → ต้องมีเหตุผล + ผู้จัดการ → คืนสต็อกตามที่ตัดจริง + คืนแต้ม/หักยอดสะสม
```

## 9. ความปลอดภัยและความถูกต้องของข้อมูล

- PIN เก็บเป็น scrypt hash + salt, เปรียบเทียบแบบ timing-safe, login ผิดถูกบันทึกใน audit log
- เปลี่ยน PIN / ปิดผู้ใช้ ⇒ ลบ session เดิมทันที
- ทุกการเขียนเงิน/สต็อกอยู่ใน `BEGIN IMMEDIATE` transaction (rollback อัตโนมัติเมื่อผิดพลาด)
- ตรวจ input ทุก endpoint, SQL ใช้ prepared statements ทั้งหมด, HTML escape ทุกค่าที่แสดง
- ไม่ลบข้อมูลที่มีประวัติ (สินค้า/วัตถุดิบใช้ soft delete, บิลใช้สถานะ void)
- ต้องมีเจ้าของร้านที่ใช้งานอยู่อย่างน้อย 1 คนเสมอ
